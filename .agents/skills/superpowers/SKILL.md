# Superpowers — 工程流程入口

- 先確定當前工作目標，再選需要的流程；不因啟動或每次工具呼叫而讀取所有技能。
- 有已安裝的 Superpowers Plugin 時，直接使用該 Plugin 的相關能力，**不要重新安裝或複製整套**。官方專案：https://github.com/obra/superpowers
- 規劃、偵錯、實作、測試、交付是不同情境，不是一條需要全部讀取的載入鏈。只有當前步驟需要時才讀它。
- 當前 LOC 專案以 `AGENTS.md` 與現行程式碼為準；Skill 不是自動授權改動其他模組。
- 如需過往專用技能原文，只在確認必要時查 `.agents/SKILL-LINKS.md` 的固定版本連結。

## Bug 修復到交付的閉環

1. **自己先取得證據**：確認 main 及工作範圍、實際錯誤、第一個異常邊界與可重現步驟；需要時按需查 `.agents/SKILL-LINKS.md` 的 DevTools／效能／除錯指引，不用舊記憶取代現況。
2. **實作後自己驗證**：執行能針對原 Bug 失敗的聚焦測試，必要時檢查真實 API、瀏覽器 Network／Console、回應、Session、畫面或手機端，不只看語法、Build、Preview 成功。測試碼未實跑不可拿來交付給使用者代測。
3. **交付到 main**：依現有 Git 流程提交與合併，核對 main 的 SHA 與實際部署版本，確認原問題已解決、相關功能未倒退；Preview 正確而 main 仍錯是未完成，不能標成已修復。
4. **避免盲測迴圈**：每次重試先明確提出假設與能排除假設的觀察；若輸出與前次相同，不再換個說法請使用者重試或再次部署。同一假設遇到反證就立即回到使用者原需求與首個失效點，改查不同故障層；避免初始偏差在後續幾個決策放大，但不因此停止正常修復與交付。
5. **只索取真正有用的協助**：受權限或私人登入限制，確實無法自行取得資料時，僅問一個可立即區分原因的具體關鍵，說明 A／B 結果導向何處；不索取秘密值，不預設要求安裝或開放管理 MCP。
6. **清楚區分狀態**：修正已寫、測試通過、Preview 有效、合併 main、主線實測有效是不同狀態。無法完成最後一段，報「未驗證／未完成」與阻礙，不得報完成。
